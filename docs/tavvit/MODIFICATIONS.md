# What Tavvit changes from Backspace

Tavvit is Backspace 1.11.0 (upstream commit `2885a7d3`, "fix(web): author menu and
sticker picker follow-ups (#466)") with the changes below, made in **October 2026**.
This file is the notice the AGPL asks for (§ 5(a)): which files were changed and what
the changes are. Everything not listed here is Backspace's code, unchanged. Where a
change was made to an existing file, that file's own history is in git
(`git log --follow <file>` against the base commit).

The license of every change is the same as the code it changes: AGPL-3.0-only. See
[LICENSING.md](LICENSING.md).

## 1. Private by default

| Area | Change | Main files |

## 3. Navigation and the friend-group experience

- **Home** page (`components/home/HomePage.tsx`): a greeting, friends currently on
  voice (with a *Join* button), unread conversations, pending friend requests and your
  spaces, all from data the client already holds. New accounts see how to start.
- **Activity panel**: friends on voice show the space they are in
  (`components/layout/ActivityPanel.tsx`, `utils/homeSummary.ts`).
- **Pages**: `/friends` (the friends list moved off the Home route), `/about`
  (replaces `/backspace`, which redirects). Sidebar: Home, Friends, Explore, About.
- **About** page (`components/about/AboutPage.tsx`): server name and address, version, the
  legal links with the source offer.
- **Sign-in page**: shows the server's name, explains "invite only", and when no
  account exists yet, the one command that creates the first administrator.
- **Mobile**: tapping a friend opens (or creates) the conversation with them; friends
  on voice are ringed.

## 5. Deployment tooling

`install.sh` (private defaults, builds from the checkout, creates the administrator,
restores executable bits), `update.sh` (`--from <archive>`, `--check`, rollback logic
by image id, runs without the executable bit), `backup.sh`, `restore.sh` (sudo
fallback), new `doctor.sh` and `tavvit-admin.sh`, `scripts/package-release.mjs`,
`docker-compose.yml` (builds `tavvit:local`, never pulls), `Dockerfile` (CRLF-proof
entrypoint), `.env.example`, `Caddyfile` comments, `.gitattributes` (LF endings).

## 6. Documentation

`README.md` (rewritten), `docs/tavvit/*` (new), `NOTICE` (Tavvit preface and brand
section), `assets/brand/README.md`.

## 6a. Added since

Sign-in and account security: Argon2id, sessions, the sign-in delay (`docs/systems/auth.md`); mail, addresses and password reset, with `nodemailer` as a new dependency (`docs/systems/email.md`). Two-factor authentication and security activity, with `qrcode-generator` as a new dependency of the web client (`docs/systems/auth.md`).

Roles and badges: clickable badges, and a library of role icons from Phosphor (MIT) in place of emoji (`packages/web/src/badges/`, `packages/web/src/roles/`, `docs/systems/badges.md`). The look: a deeper ground, ambient light in the colour of the place, motion tokens, large type, a mark that slides between places (`docs/systems/design-system.md`). The administration: a console of its own at `/admin` in place of the settings tab, with a dashboard, announcements, sign-up rules, starter spaces, a system page, a search across the instance, CSV exports, and per account its sessions, security activity, notes and warnings (`packages/web/src/components/admin/`, `packages/server/src/routes/adminConsole.ts`, `docs/systems/admin.md`).

Message tools (1.23.0): pinned messages, spoilers for text and files, deleting several messages, forwarding, polls, a task in the browser before an account is created, and push to a closed app (`docs/systems/push.md`).

Community (1.24.0): threads, events in a space with reminders and a calendar file, a welcome page with rules that can be required before taking part, and incoming webhooks with accounts that cannot sign in (`users.account_kind`). English is now the default language everywhere: the browser's and the system's languages are no longer asked, and another language comes only from a person's own choice.

The extras (1.25.0): voice messages recorded in the browser with a waveform and a speed control, saved messages with reminders, keyword alerts through the shared alert rule, and a soundboard whose clips each listener plays on their own device.

Bots and API (1.26.0): accounts run from a program, deny by default on every route and socket event, a token shown once, a switch for the operator (off by default), a developer page, an invite page, slash commands, and a guide with an example bot in `docs/bots/`. Also: writing in a channel now takes VIEW_CHANNEL as well as SEND_MESSAGES.

Bluesky in the chat (1.40.0): a link to a post on Bluesky becomes a card of the post (`docs/systems/embeds.md`, "Bluesky posts"). The server reads it from Bluesky's public interface (`utils/bluesky.ts`, `com.atproto.identity.resolveHandle` and `app.bsky.feed.getPosts`) and keeps what the card shows in `embeds.data` (migration 0076, additive) as a `BlueskyPost` (`packages/shared/src/bluesky.ts`): author, text with its links, mentions and hashtags (facets cut by bytes), one to four pictures, a video, a link card, a quoted post, the counts, and whether it is labelled sensitive; a withdrawn post gets no card, one that cannot be read an ordinary preview. Every address is checked against Bluesky's own hosts where it is made and wherever one arrives (`blueskyPostOf`). The card shows the text at once and the pictures and video after one consent for Bluesky's hosts; a video plays through the light build of hls.js (a new dependency, Apache-2.0, loaded on the first play) with Tavvit's own controls; the CSP's closed `connect-src` names Bluesky's two video hosts. Pictures open in a new media viewer (`MediaViewer.tsx`, in place of the image preview) with a strip, zoom, Open in browser, Copy link, Copy, Save, and the message's Reply and Forward; Copy and Save fetch a Bluesky picture through `GET /api/embeds/bluesky-picture`, since its host sends no CORS headers. The privacy draft names both requests to Bluesky.

Theme studio (1.41.0): a look (`packages/web/src/utils/looks.ts`) is the surfaces, accent, light, corners, typeface, picture shape, message style and density as one thing; what helps reading (contrast, text size, motion, status palette, underlined links, clock, sidebar width) is never part of one (`docs/systems/design-system.md`, "Looks and the theme studio"). The studio at `/studio` shapes it beside a sample conversation drawn with the real classes; looks are kept under a name in this browser only (`stores/looksStore.ts`, at most 30); a look travels as a link whose fragment holds all of it (`/look#1.…`), read by a public page that puts it on with one click, so no server stores or sees it. A space can choose its colours (`SpaceLook` in `packages/shared/src/looks.ts`, `spaces.look`, migration 0077, additive; `PATCH /api/spaces/:id` `look`, MANAGE_SPACE, `400 space_look_invalid`), which its members see while in it unless they switch that off (`docs/systems/spaces.md`, "A space's look"). The Appearance settings were split into reusable controls shared with the studio. A change of a space's tag or look is now recorded in its audit log.

Staying in the call (1.41.1): the client now takes its voice session over on the first `ready` of every new socket while LiveKit is live, also when the server still lists it in its reconnect grace (`useWebSocket.ts`, `voiceSessionIsLive`); it used to skip that case, and the server ended the session a minute later while the person still talked in LiveKit, so they vanished from the channel for everyone and watching together refused them (`docs/systems/voice.md`, "Transient reconnects"). The takeover answers with the call's `watch_state`. Deleting a DM message goes through one function (`utils/dmMessageDeletion.ts`, REST, socket, report and relay alike) whose `dm_message_deleted` names the conversation's preview now, and the client follows it and edits of the preview message, so no list keeps showing a deleted message (`docs/systems/dm-system.md`, "Delete Message"). The phone's conversation list uses the desktop's menu (closing a conversation with one person, leaving a group after asking), and a refused close or leave says why.

Stronger colours, nicer bots (1.41.2): the developer portal (`components/developers/BotPortalPage.tsx`) was redesigned from a community contribution into a frame of its own with the bots down the side, three facts and five tabs, reworked onto the design system. Bots get a banner and a username of their own under a person's rules (`PATCH /api/bots/:id`, `docs/systems/bots.md`, "The portal"), and their changes reach everyone at once. Accounts that are not people take no friend request or conversation by an explicit rule (`utils/contactPolicy.ts`), a request naming one answers `friend_request_not_person`, and clients no longer offer it (`isPersonAccount`). A profile theme has a strength (`users.profile_theme_style`, migration 0078, additive): soft as before, strong, or full with the text on a dark panel (`docs/systems/design-system.md`, "Profile themes").

New badges, nicer tags, sound for everyone (1.41.3): the badges are the flat marks of a new sheet (`assets/badges v3.png`, 8 by 8), cut out as drawn by a rewritten `scripts/badges/cut.mjs` (rows and columns found as the bands of its ink, the ground taken away pixel by pixel, one frame for every mark, 96px WebP), and the registry gives each a category (`BADGE_CATEGORIES`) that its card names. Beside a name they stand in one strip on the sheet's ground after the pronouns, and the card is small, the picture on a stage of that ground in a light of its own colour (`docs/systems/badges.md`). Space tags are drawn as a plate with the space's colour as a seal (`docs/systems/space-tags.md`, "Design"), and keep to the first line in the lines look. A message from three or more calendar days back shows its date with its time (`utils/messageTime.ts`, `formatShortDateTime`), and the lines look widens its time column for such a day. Watching together: a start the browser refused was never reported for YouTube or Vimeo, since the room's ask every second set the check back each time; nobody took back a mute YouTube keeps on the device; and a video playing muted counted as playing, so some people heard nothing and were never asked to click. The check now runs once per attempt, the whole sound is told when ready and on every change, silence against the volume counts as refused, and the click resumes with the sound (`docs/systems/watch-together.md`, "A start the browser refuses"). A file plays on the call's output device; for YouTube and Vimeo, which cannot, a person whose call uses another device is told once. The mark of a voice channel's OBS overlay gives its place to the settings gear under the pointer. No migration.

Live in purple (1.39.1): while someone has a `streaming` activity (live on Twitch), their status dot shows streaming in place of online, idle or do not disturb, a purple disc with a play mark cut out (`--status-streaming`, Avatar's `streaming`, `useStreaming` in `stores/activityStore.ts`, `docs/systems/activity-presence.md`, "Streaming on the dot"). Only the dot: the status, the alert gate and notifications are unchanged.

Moderation for administrators (1.39.0): an instance administrator takes content away directly instead of only through reports (`docs/systems/admin.md`, "Removing content"): a message in a space from its menu, parts of a person's profile (picture, banner, display name, about me, status, pronouns, links, decorations, the space tag worn), parts of a space (icon, banner, description, tag), one of its emoji, stickers or sounds, or the whole space, from the console. Each names a reason and a ground, sends the person it concerns a notice with how to object (new kinds `profile_content_removed`, `space_content_removed`, `space_removed`, whose subject names the parts by key so the client says them in the reader's language), and writes the platform audit log (`message_remove`, `profile_content_remove`, `space_content_remove`, `space_delete`). New routes in `routes/adminRemoval.ts`, behind `requireAdmin`; direct messages are not among them, and a copy of someone whose home is another instance is left to that instance (`AdminUser.profileKeptByHome`). Removing a space's emoji, sticker or sound now goes one way for its own managers and for an administrator (`utils/spaceExpressionRemoval.ts`), and relaying a changed profile is one function whoever changed it (`utils/profileRelay.ts`). One dialog asks for every removal (`AdminRemovalDialog`), the made decorations' removal included. A deleted space now leaves its members' lists at once (`space_deleted`, sent by `deleteSpaceCompletely` whoever deletes it). The terms draft names deleting a space and removing parts of a profile or a space among the provider's measures. No new tables, no migration.

Smoother (1.38.1): a performance pass, measured on a production build with a busy channel and a long member list. Decorations at rest have no animation at all instead of a paused one (a paused animation keeps a compositing layer, and everything it overlaps gets one too): every animated part of a frame, a nameplate or a name names its animation through `--deco-move`, which is `none` where it rests (`docs/systems/decorations.md`), and the decorations panel's tiles rest until pointed at; a channel with its member list went from 375 layers to 21. `Message` is memoized and reads only what it shows from the stores (`memberByUserId` indexes the roster), finds the topmost visible row by halving on each scroll, and skips hover while the list scrolls (`utils/listScroll.ts`). A channel left at its newest message keeps only its newest page in the cache. Animated profile pictures stand on their first frame (a canvas, `StillPicture.tsx`) except where their frame would move. `useDelayedLoading` could leave a skeleton on screen for good when loading ended in the moment it appeared; it now follows both states. Origins' hosts are cached (`normalizeOriginToHost`).

Decorations people make (1.38.0): anyone can make a frame or a nameplate from a picture they upload, an effect from one small piece and one of Tavvit's motions (fall, tumble, rise, float, twinkle), or a name style from one of seven looks and their colours, wear it, and share it in the instance's community gallery, where everyone can wear it with one click (`docs/systems/decorations.md`, "Made by people"). New table `custom_decorations` (migration 0075, additive); a profile wears a design by its reference, `custom:<id>`, in the existing decoration columns, which `PATCH /api/users/@me` takes only when the design exists, is of that kind and is shared or the person's own; every `User` carries `customDecorations` with what a client needs to draw it. Pictures are decoded and encoded again as WebP (a still first frame beside a moving one) under `UPLOAD_DIR/decorations/`, served without a session as immutable, named in a `User` by their path and made absolute for a person read from another instance (`normalizeUserAssets`), drawn through the consent for other servers; they count on their maker's storage, and files no design names are swept at start and hourly. None of them can cover a profile: a made frame's middle is masked clear, an effect is a few small pieces as particles rather than a picture over the card, a nameplate fades out before the name. New routes in `routes/customDecorations.ts` (gallery, one's own, make, change, delete, an administrator's removal with a notice to the maker and `decoration_remove` in the audit log, the pictures); a design is a report target (`decoration`) whose `content_removed` takes it away; removing one, or its maker taking it out of the gallery, announces every profile that wore it at once. Deleting an account removes what it made. The privacy draft gained a paragraph on decorations people make.

Decorations drawn (1.37.1): every frame, profile effect and nameplate is now a hand-made vector drawing of a thing (`components/ui/decorationArt.tsx`) instead of light, gradients and particles: flat tones with a darker outline, lit from the upper left. Frames are drawn in up to two layers, one behind the picture and one in front of it (the avatar isolates itself while it wears one); profile effects play over the whole profile card instead of its banner, measuring themselves with container units, and what moves in effects and nameplates wears a small SVG sprite; nameplates are scenes at the end of the row. Ten name effects were added (wave, glitch, sticker, comic, retro, candy cane, galaxy, toxic, lagoon, berry); the wave draws the name letter by letter and keeps it whole for screen readers. Designs that went are kept as aliases: a stored retired name shows as the drawing nearest in theme, and an update naming one stores that drawing (`RETIRED_*` in `shared/src/decorations.ts`), so no migration is needed. `CardTopEffect` and `ProfileHeaderLook.effectHeight` were removed.

For creators (1.37.0): space tags, a voice overlay for OBS and a page for creators. A space can have a tag (`docs/systems/space-tags.md`): two to four letters or digits of one script, a symbol of the role set and an accent colour, refused when it is a word reserved for the platform (`checkSpaceTag`); members wear it beside their name in messages, member lists and profiles, and a click on it opens a card with the space and a way in (`GET /api/spaces/:id/tag`). Migration 0074 adds `spaces.tag`, `users.space_tag` and `voice_overlays`. The privacy draft names the space tag among profile data and says what an overlay link shows and stores.

Badge pictures (1.36.1): the badges are matte metal marks from a new badge sheet (`assets/brand/badge sheet.png`, 8 rows of 8) instead of single-colour SVG drawings (`docs/systems/badges.md`, "Design rules"). `scripts/badges/cut.mjs` finds each mark by its edges, takes the sheet's ground, light, shadows and glows away and writes a 72px WebP per badge into `packages/web/src/badges/images/`; `BADGE_CELLS` says which mark is which badge. Badges are 2px larger (16, 18, 20), nothing lights up under the pointer, a badge's card shows it on a plain tile, and the registry no longer has a colour per badge (`tone`).

Profile decorations (1.36.0): a frame round the picture (nineteen), an effect over the profile's banner (sixteen), a nameplate behind the name in member lists (seventeen), and a style for the name, a typeface (seven besides the interface's own) and light inside its letters (eleven), chosen in Settings → Decorations with a preview, free for everyone (`docs/systems/decorations.md`). In a space, a role's colour wins over the name's effect. Linked accounts (1.35.1): a person links their Twitch account in Settings → Linked accounts by signing in at Twitch, so only their own (`docs/systems/linked-accounts.md`). The sign-in returns to a page of the app (`/linked-accounts/twitch`), which completes the link with the session signed in in that browser; the server takes it only from the account that started it (a state bound to it for ten minutes), exchanges Twitch's code for a token, asks who signed in and revokes the token at once, keeping only the account's id, login and display name (new table `linked_accounts`, migration 0072, and `users.profile_linked_accounts` for what the profile shows). The privacy draft's Twitch paragraph says what linking stores.

Camera backgrounds and streamer mode (1.35.0): the camera can blur the room softly or strongly, put the person in one of five scenes drawn for Tavvit (`scripts/camera-scenes/`), or in front of a picture of their own (`packages/web/src/camera/`). It runs on the device with LiveKit's track processors and MediaPipe's selfie segmenter (new dependency `@livekit/track-processors`, Apache-2.0, with `@mediapipe/tasks-vision`; the model `selfie_segmenter.tflite`, Apache-2.0, is in the repository), in a chunk of its own that loads the first time a background is used; MediaPipe's WebAssembly is served by the app itself under `/mediapipe/<version>/` (`packages/web/src/build/visionAssets.mjs`), kept a year by browsers and not precached. The own picture stays in IndexedDB on the device, without its metadata, and is deleted at sign-out. Streamer mode (`docs/systems/streamer-mode.md`) hides email addresses, invite links and codes, connected instances, two-factor secrets and recovery codes, session addresses, bot tokens and webhook addresses, moderator notes and what notifications and pushes say, by hand, by a shortcut, or in the desktop app by itself while OBS, Streamlabs or XSplit runs (`packages/desktop/src/streamingSoftware.ts`, over one listing of running programs shared with game detection, `processWatch.ts`); a value is not put into the page at all, and copying still works. Watching together keeps subtitles off until the viewer turns them on, and one's own profile shows no mutuals. The privacy draft says that a camera background is made on the device (`docs/systems/voice.md`, "Camera backgrounds"). A Twitch channel linked on a profile shows as the person's activity while it is live (`docs/systems/activity-presence.md`, "Live on Twitch"): with `TWITCH_CLIENT_ID` and `TWITCH_CLIENT_SECRET` set, the server asks Twitch's API once a minute about the channels of its signed-in people who share their activity (`packages/server/src/utils/twitchApi.ts`, `twitchLive.ts`), marks what it found `source: 'twitch'`, keeps it beside what the client reports and relays it to peers, which keep the mark; the profile offers a link to the stream, and only to the channel's own page. Nothing from Twitch loads in the browser, and the privacy draft says what goes to Twitch.

The product page as a place to walk through (1.34.2): the page opens on a stage (`packages/web/src/landing/Stage.tsx`), a window of the app in which the list of channels is a floor plan of Night Shift, the demo space of the page's pictures, and the room chosen stands where the app has its conversation. Every room can be used: #general to write in, the thread of raid-planning, a spoiler in clips, a poll whose results stay hidden until one has voted, the lounge to join, movie night to watch along with reactions, and the events to go to; the window's bar opens the member list under its roles and lays the seven looks on the window. No new dependency (`docs/systems/landing.md`, "What is on it").

The public website, prerendered (1.34.1): the product page and the public pages (`/status`, `/help`, `/changelog`, `/roadmap`) are rendered to HTML when the web package is built, by Astro (`astro` and `@astrojs/react`, development dependencies of the web package, used at build time only and with Astro's usage reporting switched off), from the same React components, and taken over by a script of their own; the server fills in its own origin and sends them at those addresses, while `/index.html` stays the app's page. Moving over from Discord (1.34.0): a space can have up to 200 emoji and 60 stickers of its own, managed under a new right, MANAGE_EMOJIS (bit 29), on the space settings' Emoji and stickers tab. Its emoji can be used in its channels and by its members anywhere on the instance, which the server holds to for messages, edits, forum posts, bot answers, webhook posts, direct messages written here and reactions; a forward turns the space emoji its sender may not use where it lands into text (`docs/systems/emoji.md`). A second tab, Get from Discord, holds the template import, moved there from Overview; an import of a Discord server's emoji and stickers through the person's own bot token, which is used for two requests and never stored or logged; and a text to post on Discord, whose invite link (`?from=discord`) the invite page answers with a welcome (`docs/systems/spaces.md`, `docs/systems/legal.md`). The template import now also brings over who may create threads and use the soundboard. Emoji in a channel hosted on another instance show as pictures where they showed as `:name:`, the reaction picker offers the emoji of the instance that holds the message where it used to send the home instance's ids there, and a direct message's emoji come from its writer's home, behind the consent gate while the client is not connected to it. Deleting an account now also clears it as the maker of the instance's emoji it added, which the tombstone had left in place. No new dependency. A security sweep confirmed eight of nine findings, all closed before release: a sticker has at most 300 frames and 30 seconds of encoding; an account has one picture job at a time, and the queue of waiting ones is bounded; an import keeps its outcome five minutes, so an answer lost to a timeout is asked for again; a running import is never pushed out, and one runs per account; the right is checked again right before each emoji or sticker is stored, uploads by hand included; Discord's two expression rights give Tavvit's only together; sticker ids stay in the export's file names; and browsers do not offer to save the bot token as a password.

A new product page and the first feedback of people using it (1.33.2): the product page reads like a space, its chapters in a column drawn as a space's channels that turn read as one reads, a Ctrl K switcher like the app's, and a window whose parts light up when pointed at (`docs/systems/landing.md`). Deleting an account that owns spaces (1.33.1): an administrator can delete an account together with the spaces it owns, each space on the record (`docs/systems/admin.md`).

Watching together (1.33.0): a space's voice call watches a YouTube or Vimeo video or a video file at the same moment, steered by the server's clock and held only in its memory while the call lasts, with a queue, a starter who can steer alone, reactions, a line in the channel list, and the video softened while someone speaks. The providers' players are steered over postMessage, so no script of theirs runs on the page and the CSP is unchanged, and each loads only after the person's consent (`docs/systems/watch-together.md`). No new dependency. A narrow security sweep (four read-only reviewers, a skeptic each) confirmed nine points, all closed before release: what a session may weigh and what each change sends to the call, rights taken away mid-call, a title never taken from a link, nothing named that nothing shows, and the client's own checks on what another instance may say about a channel.

Security fixes (1.32.8), after a second sweep over the areas the first did not reach, and the gate and privacy points that were still open:
- **New accounts:** while confirming an address is required, a new account does nothing in a space but read until it has; throwaway addresses are refused by a built-in list, a switch under Email that is on by default (`docs/systems/email.md`). The privacy draft says that messages are not end-to-end encrypted.
- **Storage and limits:** soundboard clips count on their creator and go with their space; group DMs are at most 100 per account and their icons are written anew; every picture field refuses an image it cannot re-encode; bot uploads hold their room first; the sidebar layout is bounded (`docs/systems/uploads.md`, `docs/systems/dm-system.md`).
- **Voice:** a space mute, deafen or lost SPEAK is enforced by LiveKit itself, calls run in voice channels only, and moderation answers no longer tell who sits in voice (`docs/systems/voice.md`).
- **Accounts:** a password confirmation counts against the account like a sign-in, waiting guesses no longer keep the owner out, and names and statuses that would disguise themselves are refused (`docs/systems/auth.md`); the list of other instances goes only to its account.
- **Privacy in the client:** banners, group and space icons wait for a yes like avatars, banners go into CSS escaped, role colours only as colours (`docs/systems/legal.md`); private categories are named only to those who see into them.
- **Federation:** a peer proves the origin it claims before it is taken or put before the admin, and only with a handshake of its own (a row an older release took from a stranger vouches for nothing); nobody peers as this instance, and a peer can no longer put people here into groups, conversations, calls or friend requests they would not take locally, nor make a row or fetch a picture here for an event that is refused (`docs/systems/federation.md`); a call room's name can never be a voice channel's, and a group's key never a 1-on-1's.
- **A remote account's secret:** the home gives the per-remote secret out only for its password and second factor, never to a session alone (`docs/systems/auth.md`, §5b).
- **Desktop:** a global shortcut is taken only when it cannot type, on any keyboard (`docs/systems/desktop-security.md`).

Security fixes (1.32.7), after a second public report and a sweep of the whole code in eight areas:
- **Address leaks:** pictures, invite icons, Outer Space cards, invites to other servers and files from peers wait for a yes in the client, `Avatar` included (`docs/systems/legal.md`).
- **Requests from strangers:** a body past 64 KiB is read only from someone who has shown who they are (`utils/bodyGuard.ts`). A socket frame is at most 64 KiB, and an account keeps at most 10 sockets (`docs/systems/websocket.md`).
- **Storage:** every writer keeps to the account's storage and the disk's reserve: forwards, follow copies, picture fields, profile pictures, stickers, exports, files from peers and uploads under way (`docs/systems/uploads.md`).
- **Outbound requests:** `safeFetch` connects only to the addresses it checked, which closes DNS rebinding (`docs/systems/embeds.md`), and ffmpeg opens only the file.
- **Rights:** moves and type changes that alter a channel's overrides need `MANAGE_ROLES`, and channel edits need sight of the channel (`docs/systems/permissions.md`). Removed members can no longer edit their messages, are out of the space's events and voice, LiveKit included, and lose their pictures for it.
- **Federation:** calls, identities, attachment types and home ids (`docs/systems/federation.md`, section 18).
- **Limits:** mail per account and per client, search, reactions per message and presence repeats.

A fix for starting (1.32.6): 1.32.5 did not start where mail goes through Resend. The webhook's plugin scope added a JSON parser of its own under the root's custom one, which Fastify 5 refuses at startup; `registerRawJsonBodyParser` (`utils/jsonBody.ts`) removes the inherited parser in that scope first. `scripts/release-check.mjs` gained the step `boot`, which starts the server as the Docker image does with every optional part configured (`docs/systems/deployment.md`, "Checking a release").

More security work (1.32.5): the server runs on Fastify 5, whose client address now also requires the connecting proxy to be on a private network (`docs/systems/web-security.md`, "The client address"); `DISABLE_RATE_LIMITS` is ignored in production; a `Permissions-Policy` header; files of messages from before 1.32.4 get names nobody can guess, a batch an hour (`docs/systems/uploads.md`); the desktop app no longer lets the page register global shortcuts that would hear typing in other programs (`docs/systems/desktop-security.md`, "Global shortcuts"); a detached account's pictures are no longer trusted on the domain it used to live on.

Security fixes (1.32.4), after a user's report that stickers from other servers loaded by themselves in DMs: a sticker, a profile picture, a banner, a space's icon or a group's icon can no longer name a file on a server of the sender's choosing, which every reader's client fetched before anyone clicked, telling that server their address and when they read; a sticker from a server the reader's client does not talk to waits for a yes like any picture from elsewhere (`docs/systems/legal.md`).
